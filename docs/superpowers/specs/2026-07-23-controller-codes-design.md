# Дизайн: получение кодов устройств с контроллера UniFi (этап 1)

Дата: 2026-07-23
Статус: утверждён (обсуждение в сессии Claude Code)

## Цель

Добавить в `unifi-fw-cache.sh` опциональное подключение к API UniFi-контроллера,
чтобы автоматически получать коды моделей **реально adopted** устройств по всем
сайтам (multi-site) и кэшировать прошивки именно для них — вместо ручного
перечисления в `--codes`.

Типичный сценарий:

```bash
sudo -E ./unifi-fw-cache.sh --auto-update-catalog --codes-from-controller \
  --api-creds-file /etc/unifi-fw-cache.creds
```

## Ключевое требование: только adopted

Берём коды **только устройств, фактически adopted на контроллере**
(`.adopted == true` в ответе `stat/device`). Устройства в состоянии
«pending adoption» (видны контроллеру, но не приняты) и тем более весь
ассортимент из firmware.json — не включаются. Поле `.model` в API контроллера
совпадает с ключами каталога firmware.json (U7PG2, UAP6MP, …).

## Не входит в объём (этап 2, отдельный спек)

Полное интерактивное меню `--interactive` со всеми режимами скрипта.
Строится после этого этапа поверх его функций.

## CLI-опции и конфигурация

Приоритет источников учётных данных: **флаги > env > файл кредов**.

| Опция | Env | Назначение |
|---|---|---|
| `--codes-from-controller` | — | Получить коды adopted-устройств со всех сайтов; включает режим `--from-catalog`. Найденные коды объединяются (union) с переданными вручную `--codes`. |
| `--list-controller-codes` | — | Только показать найденные коды (в разбивке по сайтам) и выйти. Ничего не скачивает и не пишет. |
| `--api-url URL` | `UNIFI_API_URL` | Адрес контроллера. Default: `https://localhost:8443`. |
| `--api-user USER` | `UNIFI_API_USER` | Логин локального администратора. |
| `--api-pass PASS` | `UNIFI_API_PASS` | Пароль (во флаге виден в ps — предпочтительны env/файл). |
| `--api-creds-file PATH` | — | Файл `KEY=VALUE` (UNIFI_API_URL/USER/PASS). Если права шире 600 — предупреждение. |
| `--codes-from-db` | — | Опциональная альтернатива без учётки: локальный MongoDB контроллера (`localhost:27117`, db `ace`, `db.device.distinct("model")` с фильтром adopted). Требует mongosh/mongo, работает только на самой виртуалке. |

## Новые функции (единый блок «Controller API» в скрипте)

- `load_api_creds()` — сведение флагов/env/файла кредов по приоритету;
  проверка прав файла.
- `controller_login()` — автоопределение типа API: сначала self-hosted
  `POST /api/login`; при неудаче — UniFi OS `POST /api/auth/login`
  (запомнить CSRF-токен из заголовка и использовать префикс `/proxy/network`
  для последующих запросов). Cookie-jar через `mktemp`, очистка в
  существующем `cleanup()`.
- `controller_api_get(path)` — GET с cookie (+CSRF при UniFi OS); формирует
  полный URL с учётом префикса.
- `controller_fetch_codes()` — `GET /api/self/sites` → для каждого сайта
  `GET /api/s/<site>/stat/device` →
  `jq '.data[] | select(.adopted==true) | .model'` → общий `sort -u`.
  Паттерн endpoints/jq проверен на скрипте glennr `unifi-update.sh`.
- `controller_fetch_codes_mongo()` — mongo-вариант для `--codes-from-db`.

Все вызовы curl: `-k` (самоподписанные сертификаты — норма),
`--noproxy <хост API>` (корпоративный прокси не должен перехватывать
обращение к localhost/внутреннему адресу), разумные таймауты
(`--connect-timeout`, `--max-time`).

## Поток данных

1. Парсер аргументов выставляет флаги и креды.
2. `main`: если `--codes-from-controller` или `--list-controller-codes` —
   `load_api_creds` → `controller_login` → `controller_fetch_codes`.
3. `--list-controller-codes`: печать по сайтам + итоговый список, exit 0.
4. `--codes-from-controller`: `CODES = union(CODES, найденные)`,
   `FROM_CATALOG=1`; дальше существующий конвейер
   (`process_from_catalog` → загрузки → `commit_meta` → restart).

## Обработка ошибок

- Нет curl — понятная ошибка **только** при использовании новых флагов;
  остальные режимы curl не требуют.
- Неудачный логин (обе схемы) — внятное сообщение (без вывода пароля), exit 1.
- Пустой список adopted-устройств — сообщение и exit 1 (кэшировать нечего).
- Коды, отсутствующие в каталоге прошивок, — предупреждение со списком
  «не найдено в каталоге»; остальные обрабатываются как обычно.
- Ошибка одного сайта при обходе — предупреждение и продолжение по остальным;
  если не удалось опросить ни один сайт — exit 1.

## Безопасность

- Пароль не должен попадать в логи/echo; тело логина собирается через
  `jq -n --arg` (не подстановкой в строку).
- Cookie-jar — временный файл `mktemp` с очисткой в `cleanup()`.
- Файл кредов: рекомендация chmod 600, предупреждение при более широких правах.

## Тестирование

- `bash -n unifi-fw-cache.sh` и shellcheck после правок (dev-хост Windows,
  runtime недоступен).
- Функциональная проверка пользователем на виртуалке; безопасная первая
  проба — `--list-controller-codes` (read-only).

## Критерии приёмки

1. `--list-controller-codes` показывает коды только adopted-устройств по всем
   сайтам self-hosted контроллера (и UniFi OS консоли при её наличии).
2. `--codes-from-controller` скачивает прошивки ровно для этих кодов через
   существующий конвейер (включая работу через прокси с `sudo -E`).
3. Все прежние режимы работают без curl и без изменений в поведении.
